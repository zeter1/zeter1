# Как предложить улучшение или исправление

Эта страница помогает подготовить воспроизводимый вклад в открытые репозитории профиля. У каждого проекта свои требования и ограничения; перед изменениями прочитайте его README, LICENSE (если есть), CONTRIBUTING (если есть) и открытые задачи. Отправка PR не гарантирует принятия.

## Перед кодом

1. Проверьте, есть ли уже issue или PR по этой проблеме. Для багов подготовьте минимальные шаги воспроизведения, ожидаемый и фактический результат, версию/commit и среду.
2. Для заметного изменения поведения сначала опишите цель и критерий проверки в issue, чтобы избежать лишней работы.
3. Не публикуйте секреты, персональные данные, клиентские документы, приватные дампы или непроверенные исполняемые файлы. Скриншоты и логи обезличивайте.

## Изменение и проверка

1. Создайте fork или отдельную ветку; держите патч небольшим и относящимся к одной проблеме.
2. Обновите тест или добавьте регрессию для исправляемого дефекта. Выполните команды из README/документации именно этого проекта; явно укажите непройденные или недоступные проверки.
3. В PR опишите **проблему → изменение → как проверить → ограничения**, приложите ссылку на issue и, если нужно, безопасный скриншот.
4. Не обходите проверки CI ради зелёного статуса. Зелёный CI на другом commit не проверяет ваш патч.
