## Перед созданием issue

1. Запишите точную версию или commit, способ запуска и текст ошибки. Сначала сохраните важные данные; не обновляйте программу и не очищайте настройки только ради отчёта.
2. Посмотрите README и поищите точный текст ошибки или название функции в **Issues** проекта, включая закрытые обращения. Если нашли ту же проблему, добавьте сведения о своей версии и сценарии к существующему обращению.
3. Если приложение создаёт диагностические файлы — сохраните последнюю проблемную сессию до повторных запусков или очистки данных.
4. Уберите из логов и файлов личную информацию, секреты и данные, которые не должны быть публичными.

## Шаблон для копирования

Заполните известные поля; если что-то неизвестно, так и напишите. Для длинной операции укажите этап и примерное время сбоя. Скриншот или небольшой фрагмент лога прикладывайте только после проверки на личные данные.

```text
Программа и версия / commit:
Способ запуска: готовая сборка / исходники / браузер
Windows или браузер и его версия:
Шаги воспроизведения:
1.
2.
Ожидаемый результат:
Фактический результат и точный текст ошибки:
Повторяемость: всегда / иногда / один раз
Настройки, этап и время сбоя (если применимо):
Минимальный пример или безопасный фрагмент диагностики:
```

## Как предложить функцию

Откройте **Issues** нужного проекта, проверьте, нет ли похожего предложения, и выберите форму для новой функции, если она есть. Опишите задачу пользователя и результат, по которому можно понять, что функция полезна; пример интерфейса можно приложить отдельно.

```text
Программа:
Какую задачу хочу решить:
Как решаю её сейчас и что мешает:
Желаемый результат:
Пример использования без личных данных:
```

Если такого обращения ещё нет, создайте новое. Одно обращение — одна ошибка или одна функция: так проще обсуждать детали и отслеживать результат. Issues публичны; для приватных подробностей используйте контакты выше.

## Хороший bug report

Полезный отчёт обычно содержит:

- версию/ревизию приложения;
- платформу и окружение: для Web — браузер и его версию, для desktop — версию Windows;
- точные шаги воспроизведения;
- фактический результат;
- ожидаемый результат;
- настройки, влияющие на сценарий;
- небольшой релевантный фрагмент диагностики;
- информацию о том, воспроизводится ли проблема повторно.

Вместо:

> программа не работает

намного полезнее:

> Windows 11 24H2, версия X. После выбора NVENC и системного звука запись запускается, но через 8–10 секунд FFmpeg завершается. CPU-кодирование при тех же параметрах работает. Приложен релевантный фрагмент diagnostic log.

## Что не следует публиковать

Никогда не публикуйте без необходимости:

- пароли;
- API-ключи;
- OAuth-токены;
- cookie;
- приватные ссылки;
- реальные crash dumps без предварительной проверки;
- личные документы, аудио и видео;
- полный каталог пользовательских данных приложения;
- логи, содержащие личную переписку или диктуемый текст.

## Диагностика в проектах

### ZeTer Photo Editor

Укажите браузер и версию, способ запуска (`file://` или HTTP), тип документа/формата, размер изображения, bit depth/color mode для PSD/PSB, точные шаги и ошибку из DevTools Console. Для проблем импорта/экспорта полезен минимальный воспроизводимый файл без личных данных. Не публикуйте рабочие документы, если в них есть конфиденциальное содержимое.

### BizPilot

Укажите браузер, раздел приложения, последовательность действий и связано ли поведение с `localStorage`, импортом/экспортом ZIP или demo-режимом. Перед очисткой browser storage сохраните резервную копию, если данные важны.

### ZAP ZONE

Укажите браузер, GPU/WebGL-среду, режим графики, FPS-настройки, игровую ситуацию и Console errors. Для проблем AI/оружия особенно полезны точные шаги, тип оружия, действие игрока и момент, когда поведение отклоняется от ожидаемого.

### CYBER RACE

Укажите браузер, GPU/WebGL, режим качества, FPS, этап гонки и связан ли сбой с AI, оружием, Web Audio или потерей WebGL context.

### Forest Hunter

Укажите браузер, GPU/WebGL, качество графики, оружие/перки/тип противника и последовательность действий. Для performance-проблем полезны приблизительный FPS и количество активных объектов/врагов в момент сбоя.

### Screen Recorder Pro

Особенно полезны параметры capture/encoding, аудиоустройства, FFmpeg context, тайминги и сведения о GPU/мониторе.

### BSOD Investigator

Полезны безопасная диагностическая сводка, версия CDB/WinDbg и сообщения о символах. Crash dump не следует автоматически публиковать в issue.

### VoiceFlow

Укажите модель Whisper, CPU/CUDA режим, compute type, микрофон и подсистему, где возникла проблема: hotkey, capture, inference или text insertion.

### Video Translator Pro

Укажите этап pipeline: Whisper, перевод, Edge TTS/gTTS, Pause Sync, FFmpeg, финальная проверка или recovery.

### ZeTer OS

Укажите desktop/web режим и конкретный модуль. Не прикладывайте рабочее состояние или backup с личными данными.

### Vacancy Parser Pro

Укажите источник вакансий, параметры запроса и безопасную сводку диагностической сессии.

### ZeTer Video Downloader

Укажите сайт, режим видео/MP3, качество, версию yt-dlp и релевантное сообщение FFmpeg/yt-dlp. Не публикуйте cookie и приватные URL.

### Text to MP3 for Windows

Укажите голос SAPI, сценарий чтения/MP3, аудиоустройство и безопасный фрагмент диагностики.

### Windows PC Locker

Укажите настройки предотвращения сна, таймер и последовательность lock/unlock. Для безопасной базовой проверки используйте встроенный `--self-test`.
